# Формулы разделов 3.4 и 3.5 - полное объяснение для защиты

Здесь по порядку разобраны все формулы из двух подглав - (3.1)...(3.9) для контура детекции и (3.10)...(3.15) для предиктивного контура Prophet. По каждой: сама формула, что означает каждый символ и как это работает простыми словами. В конце - краткая шпаргалка на одну строку про каждую формулу.

Две главные мысли, которые держат всё вместе:

- **Контур детекции** ловит уже наступившее отклонение. В нём три независимых сигнала: z-правило (статистика по каждому датчику), Isolation Forest и ECOD (два многомерных метода, смотрят на датчики совместно). Итог - логическое ИЛИ.
- **Предиктивный контур** (Prophet) предупреждает заранее: продолжает тренд вперёд и смотрит, не упрётся ли прогноз в границу нормы. Саму норму Prophet берёт у детектора.

# Часть I. Контур детекции (3.1 - 3.9)

## Норма датчика: формулы (3.1) и (3.2)

```
m_j = (1 / N) Σ x_ij                          (3.1)

s_j = √( (1 / N) Σ (x_ij - m_j)² )            (3.2)
```

**Обозначения:** x_ij - i-е из N обучающих показаний датчика j; N - размер обучающей выборки (порядка тысячи точек); Σ - суммирование по всем обучающим точкам; m_j - среднее датчика j; s_j - его стандартное отклонение.

**Как работает.** Это «портрет нормы» каждого датчика, посчитанный на нормальной работе. Формула (3.1) - обычное среднее: где показание держится обычно. Формула (3.2) - стандартное отклонение: насколько сильно оно гуляет вокруг среднего. Считаем три шага: вычли среднее из каждого значения, возвели разности в квадрат (чтобы минусы не гасили плюсы), усреднили и взяли корень. Деление на N (а не на N-1) означает, что берём фактический разброс именно этой выборки. Эти два числа - и есть «веса» z-правила: они сохраняются после обучения и потом используются на скоринге.

**Важно для защиты.** Норму считаем по сырому 15-секундному ряду, без выравнивания и без заполнения пропусков. Если пропуски простоя заполнять повторами, разброс схлопнется, s_j занизится вдвое, и на скоринге будет поток ложных тревог. Поэтому именно сырой ряд.

## Оценка Isolation Forest: формула (3.3)

```
s_if(x) = 2 ^ ( - E(h(x)) / c(n) )            (3.3)

c(n) = 2 H(n - 1) - 2(n - 1) / n
H(k) = ln(k) + 0,5772
```

**Обозначения:** h(x) - длина пути до точки x в одном дереве (сколько разрезов её изолировали); E(h(x)) - среднее этой длины по всем деревьям леса; c(n) - типичная длина пути в дереве из n точек (нормировка); H(k) - гармоническое число; 0,5772 - постоянная Эйлера-Маскерони.

**Идея метода в одной фразе:** аномалию изолировать легко, нормальную точку - трудно. Выбросов мало и они стоят в стороне, поэтому случайными разрезами отделяются за пару шагов. Нормальная точка сидит в плотной куче соседей - её резать долго.

**Как строится дерево (обучение).** Берём обучающие точки. Каждая точка - это строка из нескольких чисел (по одному с каждого датчика); они склеены в одну точку и путешествуют вместе. Дерево строится так:
1. случайно выбираем один датчик и случайный порог;
2. точки ниже порога идут влево, выше - вправо;
3. для каждой стороны повторяем - снова случайный датчик, случайный порог;
4. так до тех пор, пока точка не останется одна.

Ключевой момент: **в одном дереве в разных узлах используются разные датчики** (то вибрация, то нагрузка, то температура). Точка проверяется по одному датчику на каждом узле, но идёт по дереву как единое целое. Поэтому метод многомерный - выброс по любому датчику или по их сочетанию изолируется быстро. Длина пути - это одно число на дерево, про всю точку, а не про отдельный датчик.

**Лес.** Одно дерево случайно, ему может не повезти. Поэтому строят около сотни деревьев, каждое из своей случайной части точек. Для точки берут среднюю длину пути по всем деревьям - это E(h(x)). Усредняем по деревьям, а не по датчикам.

**Скоринг.** Новую точку прогоняют по уже готовым (замороженным) деревьям: на каждом узле проверяют нужный датчик, идут влево/вправо, считают шаги до листа. Среднее по деревьям - её E(h(x)). Деревья не перестраиваются, точка не добавляется в обучение.

**Что делает сама формула.** E(h(x)) делим на нормировку c(n) - получаем «короче или длиннее, чем типично для дерева такого размера». Нормировка нужна, чтобы оценка не зависела от числа точек; это стандартная формула из статьи [6], её считает библиотека, мы её не пишем. Затем `2 ^ (- это отношение)` переводит результат в шкалу от 0 до 1:

| Точка | E(h(x)) | s_if |
|-------|---------|------|
| выброс (изолируется мгновенно) | близко к 0 | около 1 |
| норма (путь как у всех) | около c(n) | около 0,5 |
| глубоко в плотной куче | больше c(n) | ниже 0,5 |

**Читается так:** s_if около 1 - аномалия, около 0,5 и ниже - норма.

## Оценка ECOD: формула (3.4)

```
O(x) = max( - Σ ln F_j(x_j),  - Σ ln (1 - F_j(x_j)) )      (3.4)
```

**Обозначения:** F_j(x_j) - доля обучающих показаний датчика j, которые не больше x_j (левый хвост); 1 - F_j(x_j) - доля тех, что больше x_j (правый хвост); Σ - суммирование по всем датчикам; O(x) - итоговая оценка аномальности.

**Идея метода.** В отличие от Isolation Forest (он режет пространство), ECOD **считает хвосты**. Для каждого датчика он по обучению знает всё распределение значений и проверяет, насколько глубоко в хвосте сидит новое значение.

**Как работает по шагам:**
1. Для датчика j строим эмпирическую функцию распределения: для любого значения знаем, какая доля обучающих показаний была ниже него. Это F_j.
2. Для новой точки в датчике j берём две вероятности: «доля ниже» (левый хвост) и «доля выше» (правый хвост). Если значение обычное - обе около половины. Если значение редкое и высокое - «доля выше» крошечная; если редкое и низкое - крошечная «доля ниже».
3. Берём `-ln` от вероятности. Это превращает редкость в большое число: чем меньше вероятность (чем реже значение), тем больше `-ln`. Обычное значение даёт почти ноль.
4. Складываем `-ln` по всем датчикам отдельно для левого хвоста и для правого. Так каждый датчик добавляет свою «странность».
5. Берём больший из двух хвостов - это и есть O(x).

**Чем отличается от Isolation Forest.** Вот здесь как раз идёт **подсчёт по каждому датчику и сложение** (то, что ты сначала ошибочно приписывал лесу). ECOD складывает вклады датчиков; Isolation Forest ничего не считает и не складывает - он режет и меряет глубину изоляции. Это два разных взгляда на одни и те же данные, поэтому их и применяют вместе.

**Читается так:** чем больше O(x), тем глубже значения сидят в хвостах сразу по нескольким датчикам - тем аномальнее точка.

## Калибровка порога детекторов: формула (3.5)

```
t = mean(o) + 3 std(o)                        (3.5)
```

**Обозначения:** o - набор оценок детектора (Isolation Forest или ECOD) на обучающих точках; mean(o) и std(o) - их среднее и стандартное отклонение; t - рабочий порог.

**Как работает.** И Isolation Forest, и ECOD выдают число, а не готовое «да/нет». Чтобы решить, с какого значения считать точку аномальной, смотрим на разброс оценок самого детектора на нормальных данных и ставим порог «среднее плюс три стандартных отклонения». Если оценка новой точки выше порога t - детектор помечает её как аномальную.

**Почему именно так.** Порог не задаётся вручную и не привязан к выдуманной доле выбросов - он определяется собственным разбросом нормальных оценок. По правилу трёх сигм за такой порог на чистом нормальном фоне выходит лишь около 0,1 процента точек. То есть порог автоматически подстраивается под каждый детектор и под данные.

## z-оценка и максимум по датчикам: формулы (3.6) и (3.7)

```
z_j = (x_j - m_j) / s_j                        (3.6)

Z = max |z_j|                                  (3.7)
```

**Обозначения:** x_j - текущее показание датчика j; m_j, s_j - его норма из (3.1) и (3.2); z_j - отклонение датчика j в стандартных отклонениях; Z - максимум модуля по всем датчикам станка.

**Как работает.** Формула (3.6) отвечает на простой вопрос: на сколько сигм текущее показание ушло от своего обычного значения. Отняли среднее, поделили на стандартное отклонение. z = 3 значит «отклонение в три стандартных отклонения».

Формула (3.7) - по станку берём не сумму и не среднее отклонений, а **максимум** среди всех датчиков. Это принципиально: один выскочивший датчик всегда заметен и не разбавляется значениями нормальных. Если бы складывали или усредняли, одно отклонение размылось бы среди шести-восьми спокойных показаний и потерялось.

**Порог.** Точка подозрительна по z-правилу, если Z достигает 2,8. Порог выбран чуть ниже границы отбраковки в три сигмы - чтобы ловить в зоне раннего предупреждения, ещё до брака.

**Числовой пример.** Виброскорость: норма m = 0,8 мм/с, s = 0,15 мм/с. Показание 1,25 даёт z = (1,25 - 0,8) / 0,15 = 3,0 - порог превышен. Показание 1,20 даёт z = 2,67 - ниже порога, тревоги нет.

## Комбинированное правило: формула (3.8)

```
a = 1, если Z ≥ 2,8 или s_if(x) > t_if или O(x) > t_ecod; иначе a = 0     (3.8)
```

**Обозначения:** Z - максимум z-оценки (3.7); s_if(x), O(x) - оценки Isolation Forest (3.3) и ECOD (3.4); t_if, t_ecod - их пороги из (3.5); a - метка аномалии (1 - аномалия, 0 - норма).

**Как работает.** Итог - логическое ИЛИ трёх независимых источников. Точка считается аномальной, если сработал **хотя бы один** из них. Главный - z-правило: оно одномерное, наглядное и надёжно ловит дрейф отдельного датчика, а таких сценариев большинство. ECOD и Isolation Forest его дополняют: они добавляют аномальные сочетания нескольких датчиков, которые по одному датчику не видны. Поэтому методы не конкурируют, а перекрывают слепые зоны друг друга.

## Правило серий (персистентность): формула (3.9)

```
k_c(t) = k_c(t - 1) + 1, если канал c сработал в точке t; иначе k_c(t) = 0     (3.9)
```

**Обозначения:** k_c(t) - счётчик подряд идущих срабатываний канала c в момент t. Канал - это отдельный датчик, вышедший за порог, или общий канал многомерных детекторов.

**Как работает.** Поверх решающего правила стоит фильтр от одиночного шума. Для каждого канала ведётся свой счётчик: сработал в этой точке - плюс один, не сработал - сброс в ноль. Точка фиксируется как аномалия, только если хотя бы по одному каналу счётчик дошёл до 3, то есть отклонение держалось три показания подряд (около 45 секунд при интервале 15 секунд).

**Зачем по каждому каналу отдельно.** Так шум, перепрыгивающий от такта к такту с одного датчика на другой, серию не накапливает (каждый раз вылетает другой канал и сбрасывается). А устойчивый дрейф одного и того же датчика серию копит и проходит фильтр. То есть отсекаются случайные одиночные всплески, но пропускается реальная развивающаяся неисправность.

# Часть II. Предиктивный контур Prophet (3.10 - 3.15)

## Разложение временного ряда: формулы (3.10) и (3.11)

```
y(t) = g(t) + s(t) + h(t) + e(t)               (3.10)

y(t) = g(t) + e(t)                             (3.11)
```

**Обозначения:** y(t) - значение ряда в момент t; g(t) - тренд; s(t) - сезонная компонента; h(t) - календарные события; e(t) - случайный шум.

**Как работает.** Prophet раскладывает временной ряд на части. Тренд g(t) - общее направление (растёт, падает, держится); Prophet представляет его кусочно-линейной функцией с автоматически подбираемыми точками излома, поэтому он гибко повторяет форму ряда. Сезонность s(t) - повторяющиеся циклы (суточные, недельные); календарь h(t) - праздники и события; e(t) - то, что не объясняется, шум.

**Почему у нас (3.11).** Сезонность и календарь мы **отключаем**: завод работает круглосуточно, реальных суточных или недельных циклов в технологии нет, а на синтетических данных модель иначе нашла бы несуществующие циклы и испортила прогноз. Поэтому разложение сводится к «тренд плюс шум» - остаётся только g(t), который Prophet продолжает на 30 минут вперёд. Вместе с прогнозом модель выдаёт доверительную полосу (уровень 0,99) - это её собственная неуверенность, и важно: полоса **не** означает «норму датчика», она лишь про уверенность модели.

---

## Коридор нормы: формула (3.12)

```
[ m - 2,8 s_min,  m + 2,8 s_min ]              (3.12)
```

**Обозначения:** m - среднее нормы датчика; s_min - стандартное отклонение в минутной шкале (см. (3.14)); 2,8 - тот же порог, что и в детекции.

**Как работает и главное для защиты.** Сам Prophet не знает, какое значение датчика считать нормальным. Норму ему **даёт детектор**: m и s - это те самые значения, которые детектор посчитал и сохранил при обучении (формулы (3.1), (3.2)). Из них строится коридор «среднее плюс-минус 2,8 стандартного отклонения» - те же границы, в которых работает контур детекции. То есть Prophet отвечает за прогноз тренда, а опору для сравнения берёт у детектора.

---

## Условие вердикта: формула (3.13)

```
существует t в горизонте: y(t) < m - 2,8 s_min или y(t) > m + 2,8 s_min     (3.13)
```

**Как работает.** Предупреждение формируется, если прогноз y(t) хотя бы в одной точке ближайших 30 минут выходит за коридор нормы (3.12) - снизу или сверху. Смысл: продолженный тренд упирается в границу нормы ещё до того, как реальное показание её фактически достигнет. Это и есть упреждение - мы реагируем на прогноз, а не на свершившийся факт.

---

## Пересчёт шкалы: формула (3.14)

```
s_min = s / √n,   n = 60 / 15 = 4              (3.14)
```

**Обозначения:** s - стандартное отклонение сырого 15-секундного ряда (из детектора); s_min - стандартное отклонение усреднённого минутного ряда; n - сколько сырых показаний попадает в одну минуту (четыре по 15 секунд).

**Зачем это нужно.** Детектор хранит s по сырому ряду, а Prophet прогнозирует усреднённый минутный ряд, который спокойнее: при усреднении нескольких независимых показаний случайный шум частично гасится. При усреднении n независимых значений разброс уменьшается в корень из n раз; здесь n = 4, значит разброс падает вдвое. Если бы коридор строили по сырому s, он был бы вдвое шире нужного, и прогноз почти никогда бы его не пробивал - предупреждения не появлялись бы вовсе. Поэтому s пересчитываем в минутную шкалу, чтобы коридор и прогноз были в одной шкале.

**Числовой пример.** s = 0,15 → s_min = 0,15 / 2 = 0,075. Коридор: 0,8 ± 2,8·0,075 = от 0,59 до 1,01. Для сравнения, коридор детекции по сырому s вдвое шире - от 0,38 до 1,22.

---

## Упреждение: формула (3.15)

```
L = t_breach - t_now                           (3.15)
```

**Обозначения:** t_now - последняя фактическая точка ряда (момент, когда строим прогноз); t_breach - первый момент горизонта, в котором прогноз выходит за коридор нормы; L - упреждение в минутах.

**Как работает.** Если вердикт (3.13) сработал, считаем, за сколько минут до выхода за границу мы предупредили. Это разница между первым прогнозным выходом за коридор и текущим моментом. L - ключевая величина предиктивного контура: она показывает, насколько заранее система подняла тревогу, и именно её мы измеряем при количественной оценке в главе 4.

# Шпаргалка (одной строкой про каждую формулу)

- **(3.1)** m_j - среднее датчика, центр нормы.
- **(3.2)** s_j - стандартное отклонение, ширина нормы; считается по сырому ряду.
- **(3.3)** s_if - оценка Isolation Forest; короткий путь изоляции = выброс; около 1 аномалия, 0,5 норма.
- **(3.4)** O(x) - оценка ECOD; складывает «глубину в хвосте» по датчикам; больше = аномальнее.
- **(3.5)** t - порог детекторов: среднее плюс три сигмы их оценок на обучении.
- **(3.6)** z_j - отклонение датчика в сигмах.
- **(3.7)** Z - максимум z по датчикам станка (не сумма, чтобы не разбавлять).
- **(3.8)** a - итог детекции: ИЛИ трёх источников (z, Isolation Forest, ECOD).
- **(3.9)** k_c - счётчик серии; аномалия, если канал горяч 3 раза подряд.
